# 产品终局设计(North Star)

日期:2026-07-05
状态:与用户逐项对齐后的固化稿(信息架构、命名、房间内层次均已口头确认;Phase B 五个落地决策采用推荐方案,随本文档一并确认)
性质:方向性蓝图。各阶段实施细节由各自的 spec 定义,本文档是它们的共同锚点。

---

## 1. 愿景与定位

把定制版 Element X 从"聊天客户端 + agent 消息"演进为**通用的目标/进度管理平台**:

- 创业者:管理创业 idea 与推进进度
- 学生:提分计划与执行追踪
- 通用抽象:**项目(目标)/ 任务 / 进度**,不做场景特化的数据模型;场景差异只体现在展示层(远期可做场景预设命名)

**核心分工:聊天 = 控制层,结构化视图 = 观察层。** Agent 在对话流里接受指令、请求决策;任务/进度以 state event 沉淀,由面板和聚合视图呈现。

## 2. 领域模型 ↔ Matrix 映射(已确认)

| 产品概念 | Matrix 载体 | 备注 |
|---|---|---|
| 分组(领域) | Space | 顶层组织,低频切换的范围 |
| 项目(目标) | Room | 一项目一房间 |
| 任务 | `io.element.agent.canvas.steps` state event(key=task_id) | 已实现 |
| 任务的执行记录 | Thread(与任务一对一绑定,`thread_root_id`) | Phase B |
| 决策点 | `io.element.agent.choice_request` 消息 + 同名 state event | 已实现 |
| 项目元数据 | `io.element.agent.goal` state event(key="") | Phase C |
| 主对话流 | 房间时间线 | 项目的总控制台 |

多任务并行是常态:一个项目(房间)内多个任务各绑一个 thread。任何"单任务假设"的 UI(如现 banner)都是过渡形态。

## 3. 信息架构(已确认)

### 3.1 底部四 tab

```
[项目]   [任务]   [消息]   [搜索]
Projects  Tasks  Messages  Search
```

- **项目**:目标房间列表(改造自现 Chats tab),回答"我该看哪个项目"
- **任务**:跨项目任务聚合(今日已上线 V1),回答"我该干哪件事";终局演化为看板
- **消息**:DM 与非项目房间。项目房间与普通房间靠 `io.element.agent.goal` state event 区分
- **搜索**:保留现状

### 3.2 分组(原 Spaces):顶部切换器,不占 tab

- 项目 tab 顶部显示"当前分组名 ▾",点开面板:分组列表(切换范围)+ "管理分组"入口
- 切换分组后,项目列表与任务看板都过滤到该分组
- 现有 Space 管理界面全部保留,仅迁移入口
- 参照 Slack:workspace 切换在 iOS 是左缘抽屉(近零可见性);我们改用顶部显式入口换可发现性

### 3.3 项目 tab(Home)内容结构

```
┌ 当前分组名 ▾
├ 【需要你】横条(有 pending 决策才显示)→ 跨项目 choice_request 聚合
├ 项目卡片列表:项目名 | 任务进度(5/8)| 最近动态一行 | 未读・待决策红点
├ 排序:有待决策 → 有活跃任务 → 最近活动
└ 空态:引导创建第一个项目
```

## 4. 房间(项目)内层次(已确认,Phase B 主战场)

```
项目房间
├ 顶部进度 chip:"3 个任务进行中 · 1 个待决策"(替代现单任务 banner)
│   └ 点击 → 房间任务面板
│       ├ 【待决策】区:本房间 pending 的 choice_request(点击滚动到卡片)
│       ├ 【进行中】任务列表:标题 | 步骤进度 | 点击 → 任务详情
│       ├ 【已完成】折叠区
│       └ 任务详情:步骤列表(已实时更新)+ "查看讨论" → 跳转绑定 thread
└ 时间线:主对话流(卡片仍在此出现,作为事件流的一部分)
```

### Phase B 五个落地决策(推荐方案,已随本文档确认)

1. **banner 处置**:直接替换为多任务进度 chip(单任务时显示任务名,多任务显示计数)
2. **面板形态**:push 页,与现有 `CanvasStepsScreen`(任务详情)构成两级导航,复用现导航栈
3. **thread 绑定 V1**:单向——任务详情里"查看讨论"跳转 thread;thread 内显示任务状态条留到后续
4. **待决策进面板**:进,作为面板顶部独立区(数据自 `fetchedStateEvents`,现成)
5. **已完成任务**:面板内折叠区展示,不设时限;"N 天后隐藏"的归档策略留给 Phase D 数据量大了再说

## 5. 任务 tab 终局

- V1(已上线):按"进行中/已完成"分组的列表
- 终局:看板视图,按项目分列 ↔ 按状态分列可切换;条目点击 → 对应房间的任务详情(而非仅房间)
- "需要你"聚合与项目 tab 共享数据源

## 6. 协议演进

已定稿部分见 `~/homelab/element-agent-protocol.md`(hermes 适配规范)。演进字段:

| 字段/事件 | 阶段 | 用途 |
|---|---|---|
| `thread_root_id`(canvas.steps state) | B | 任务↔thread 绑定 |
| `updated_at` / `priority` | B/C | 排序 |
| `io.element.agent.goal`(房间级 state) | C | 项目名/描述/状态;项目 tab 与"项目房间"判定的数据基础 |

原则:字段只增不改语义;客户端对缺失字段一律降级显示,老数据永远可读。

## 7. Slack 参照系(结论)

**采纳**:Home/DMs 分离;workspace 不占 tab;Canvas-per-channel(=房间任务面板);Slack Lists 的"条目↔thread"交互(=任务详情跳 thread);Activity 概念改造为"需要你(待决策)"聚合。
**不采纳**:把 Lists/Canvas 埋进 Files 二级入口(Slack 里任务是附属,我们这里任务是主产品,必须一等 tab);More tab 式的功能堆叠。
